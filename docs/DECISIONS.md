# Décisions d'architecture (phase 3 : API, authentification, sécurité)

| #   | Sujet                         | Décision                                                                                                                                  | Pourquoi / coût                                                                                                                                                      |
| --- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Transport de session          | Cookie `vm_session` : `HttpOnly`, `SameSite=Strict`, `Secure` (prod), jeton aléatoire 256 bits                                            | Inaccessible au JavaScript (XSS) ; envoyé uniquement en navigation même site                                                                                         |
| D2  | Stockage des sessions         | Table `sessions` : SHA-256 du jeton seulement ; une session par utilisateur                                                               | Une fuite de la base ne donne aucun jeton utilisable                                                                                                                 |
| D3  | Validité d'une session client | Toujours vérifiée contre `machine_state` (propriétaire + début de session)                                                                | Une seule source de vérité ; pas de divergence HTTP / machine                                                                                                        |
| D4  | Session administrateur        | Inactivité 30 min, durée absolue 8 h, sortie de maintenance à la déconnexion                                                              | Limite l'exposition d'un poste laissé ouvert                                                                                                                         |
| D5  | Identifiants                  | Client : PIN à 6 chiffres (suites et répétitions refusées). Admin : mot de passe ≥ 12 caractères                                          | Le PIN seul ne résiste pas à une attaque hors ligne : voir D6 et D7                                                                                                  |
| D6  | Hachage                       | argon2id + **poivre** serveur (HMAC) hors base                                                                                            | Sans le poivre, une base volée ne permet pas de retrouver un PIN (1 million de combinaisons)                                                                         |
| D7  | Anti-force-brute              | 5 tentatives, verrouillage 5 min. La tentative est **réservée atomiquement avant** la vérification                                        | Des essais parallèles ne dépassent jamais 5 vérifications. Coût : un tiers peut verrouiller un compte (déni de service ciblé)                                        |
| D8  | Énumération de comptes        | Inconnu, mauvais PIN et compte verrouillé : réponse identique, vérification factice de même coût                                          | Ne révèle ni l'existence ni l'état d'un compte                                                                                                                       |
| D9  | CSRF                          | `SameSite=Strict` + refus de toute `Origin` inconnue sur les requêtes qui modifient l'état                                                | Défense en profondeur sans jeton supplémentaire                                                                                                                      |
| D10 | Lectures vs actions           | Seules les actions (dépôt, commande, déconnexion) comptent comme activité ; lire ne prolonge pas la session                               | Une page qui interroge en boucle ne bloque pas la machine                                                                                                            |
| D11 | Dépôt                         | Un billet par requête, `insertionId` (uuid) fourni par le client, liste blanche de coupures                                               | Dans cette simulation le navigateur joue le rôle du matériel : la frontière de sécurité est la liste blanche, le plafond, l'authentification et l'état de la machine |
| D12 | Comptes                       | Pas d'inscription publique : l'admin crée les clients ; le premier admin vient d'un script (`seed:admin`)                                 | Aucune route ne permet de créer un administrateur                                                                                                                    |
| D13 | Droits de la base             | Rôle applicatif sans écriture directe sur solde, stock, registres ni schéma (`pnpm db:roles`, voir D31) ; déclencheurs `SECURITY DEFINER` | Un bug ou une injection ne peut pas créer d'argent. Coût : un rôle à déployer                                                                                        |
| D14 | Erreurs                       | Format `{error:{code,message,details?}}` ; 500 générique sans détail ; 503 + `Retry-After` si verrou indisponible                         | Aucune fuite d'information interne                                                                                                                                   |
| D15 | Journaux                      | pino ; aucun cookie, jeton ni secret ; `requestId` dans les 500                                                                           | Diagnostic sans fuite                                                                                                                                                |
| D16 | Limitation de débit           | Globale 300/min/IP ; connexion 10/min/IP ; dépôt 60/min/IP                                                                                | Complète le verrouillage par compte                                                                                                                                  |
| D17 | Démarrage / arrêt             | Validation de la configuration, **reprise des commandes interrompues avant d'écouter**, arrêt propre sur SIGTERM/SIGINT                   | Une distribution interrompue est toujours clôturée                                                                                                                   |
| D18 | Audit                         | Actions admin et connexions admin, dans la même transaction que l'action                                                                  | Journal fiable et append-only                                                                                                                                        |
| D19 | Configuration                 | Variables d'environnement validées (Zod) ; refus de démarrer avec un poivre d'exemple ou `COOKIE_SECURE=false` en production              | Pas de configuration dangereuse par oubli                                                                                                                            |
| D20 | Limites de stock              | Réapprovisionnement 1 à 1 000 par opération, stock maximal 10 000                                                                         | Évite les valeurs absurdes                                                                                                                                           |

# Décisions d'architecture (phase 5 : interface)

| #   | Sujet                         | Décision                                                                                                                                                                                               | Pourquoi / coût                                                                                    |
| --- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| D21 | Stack                         | React 19, Vite, TypeScript strict, Tailwind 4, TanStack Query ; pas de routeur                                                                                                                         | L'état de la session (client / admin / résultat) décide de l'écran : un routeur n'apporterait rien |
| D22 | Même origine                  | L'interface appelle `/api/...` ; le proxy Vite (puis le proxy de production) retire le préfixe                                                                                                         | Cookie `SameSite=Strict` sans CORS. Il faut ouvrir `http://localhost:5173` (l'origine autorisée)   |
| D23 | Contrat partagé               | Types et codes d'erreur dans `@vending/shared` ; le serveur ne peut émettre que les codes de la liste, l'interface a un message pour chacun (type exhaustif)                                           | Aucun message oublié, aucune dérive serveur / interface                                            |
| D24 | Temps de session              | Calculé par le **serveur** (`remainingMs`), l'interface décompte localement et se resynchronise toutes les 10 s                                                                                        | Pas d'écart d'horloge entre le client et la machine                                                |
| D25 | Réponse perdue                | Dépôt : bouton « Réessayer » qui réutilise le même `insertionId`. Commande : même `Idempotency-Key` tant que le panier ne change pas. Session fermée ensuite : message honnête (« peut-être traitée ») | Jamais de double débit, et jamais de message qui incite à recommander                              |
| D26 | Confidentialité entre clients | Les données de session sont vidées dès que l'écran du client est démonté ; le secret saisi est effacé après connexion                                                                                  | Le client suivant ne voit rien du précédent                                                        |
| D27 | Le serveur reste juge         | Plafonds, stock, solde : l'interface les affiche et bloque les actions impossibles, mais chaque règle est revérifiée côté serveur                                                                      | L'interface est de l'ergonomie, pas de la sécurité                                                 |
| D28 | Accessibilité                 | Clavier complet, libellés associés, `aria-live`, focus sur le résultat, lien d'évitement, cibles de 44 px, mouvement réduit ; vérifiée par axe-core sur tous les écrans                                | Le **contraste** n'est pas mesurable sans navigateur : à contrôler en CI (phase 6)                 |
| D29 | Langue                        | Français ; textes centralisés (`src/i18n/fr.ts`)                                                                                                                                                       | Traduction ultérieure possible sans toucher aux composants                                         |

# Décisions d'architecture (phase 6 : déploiement et exploitation)

| #   | Sujet                                 | Décision                                                                                                                                                    | Pourquoi / coût                                                                                             |
| --- | ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| D30 | Production du serveur                 | Un bundle (tsup), dépendances npm installées dans l'image, pas de TypeScript à l'exécution                                                                  | Démarrage rapide, image petite ; le paquet interne `shared` est inclus                                      |
| D31 | Rôle de la base                       | `db:roles` (idempotent) remplace le script SQL ; relancé après chaque migration                                                                             | Testable, validé contre l'injection ; les nouvelles tables n'héritent pas des droits                        |
| D32 | Suite de tests sous le rôle restreint | Les tests HTTP se rejouent avec `TEST_APP_ROLE=1`                                                                                                           | Un test de fumée avait révélé un `INSERT` interdit que la suite (propriétaire) ne voyait pas                |
| D33 | Point d'entrée                        | Caddy : fichiers statiques + `/api`, HTTPS automatique, CSP stricte                                                                                         | Même origine ; trois modes d'adresse dans un seul fichier                                                   |
| D34 | Domaine gratuit                       | Tailscale Funnel (maison/NAT), DuckDNS + Caddy (serveur public), tunnel rapide (démo)                                                                       | Non testés ici ; seul le Caddyfile l'est                                                                    |
| D35 | Conteneurs                            | Utilisateur non root, API en lecture seule sans capacités, base et API jamais publiées                                                                      | Réduit l'impact d'une compromission                                                                         |
| D36 | Sauvegarde                            | `pg_dump` au format personnalisé, somme de contrôle, restauration **seulement dans une base vide**                                                          | Évite d'écraser des données par erreur ; testée avec comparaison table par table                            |
| D37 | Poivre                                | Ne figure pas dans les sauvegardes ; sa perte invalide tous les PIN                                                                                         | Choix de sécurité assumé (documenté dans le RUNBOOK)                                                        |
| D38 | CI                                    | Actions épinglées par empreinte de commit vérifiée ; droits minimaux ; audit ; analyse de secrets ; images et déploiement construits et testés ; Playwright | `actionlint` et l'analyse de secrets ont été exécutés ; les tâches Docker et Playwright ne le sont qu'en CI |
| D39 | Qualité                               | ESLint (promesses oubliées, hooks, accessibilité) + Prettier dans `pnpm check`                                                                              | Deux alertes ont mené à de vraies corrections de conception                                                 |
| D40 | Limites de débit                      | Réglables par variables d'environnement, avec bornes                                                                                                        | Un quota par IP est partagé derrière un NAT                                                                 |
| D41 | Purge                                 | Sessions mortes supprimées au démarrage puis toutes les heures                                                                                              | Évite l'accumulation sans toucher aux sessions vivantes                                                     |
